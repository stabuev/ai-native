Проблема: код успешно исполнился, но ответ всё равно неверен

В 5.1 был утверждён план:

Вопрос: какие регионы принесли больше оплаченной выручки в Q2?
Источник: sales.csv.
Grain: одна строка = один заказ.
Фильтры: quarter = Q2, status = paid.
Метрика: paid_revenue = SUM(amount), RUB.
Разрез: region.
Ожидаемо: прочитано 6 строк, использовано 4, общий итог 200.

Теперь модель пишет Python:

import pandas as pd

df = pd.read_csv("sales.csv")
selected = df.query("quarter == 'Q2'")
result = selected.groupby("region")["amount"].sum()

Код синтаксически корректен. Изолированная среда запускает его без ошибки и возвращает:

Москва = 150
Питер = 100
Казань = 20
Итого = 270

Среда выполнила свою работу: код не получил лишнего доступа к компьютеру и завершился успешно. Но модель забыла фильтр status == "paid", поэтому в Питер попал возврат 70. Успешное исполнение не означает правильный анализ.

Отсюда два независимых вопроса:

  1. Можно ли безопасно исполнить этот код?
  2. Соответствует ли код утверждённому плану и данным?

Code Interpreter помогает с первым вопросом. Ответственность за второй остаётся у человека.

Центральная модель

Что такое Code Interpreter

Code Interpreter — это не отдельная модель и не способность LLM безошибочно считать «в уме». Это рабочий контур:

утверждённый план
        ↓
модель предлагает код
        ↓
отдельная среда исполняет код
        ↓
возвращает результат, ошибку и созданные файлы
        ↓
человек проверяет код и доказательства

В разных продуктах эта возможность может называться data analysis, Python tool или code execution. Название меняется, а роли остаются:

  • Модель переводит задачу в код и при необходимости предлагает исправление.
  • Среда исполнения запускает код с заданными возможностями и ограничениями.
  • Человек подтверждает смысл расчёта и принимает результат.

Sandbox и container обычными словами

Sandbox, или песочница, — среда, которая отделяет недоверенный код от основной системы. Код получает не весь компьютер, а только разрешённую рабочую область.

Container, или контейнер, — один из способов предоставить такую отдельную область: собственные процессы, файлы, библиотеки и лимиты. Некоторые платформы используют контейнеры, другие описывают среду иначе. Для пользователя важен не бренд технологии, а проверяемая граница доступа.

Функция Python exec(text) исполняет переданный текст как код в текущем процессе. Ограничение доступных ей функций не создаёт отдельную защитную границу: код всё ещё может зависнуть, исчерпать память или воспользоваться переданным ему объектом. Поэтому в этом уроке мы не запускаем произвольный код модели локально и не собираем псевдо-sandbox.

Capability: что среде разрешено

Capability, или возможность среды, — конкретное действие, которое она разрешает коду. Перед рабочим запуском нужно выяснить:

ГраницаЧто проверить
Входные файлыКакие файлы доступны и как подтверждается их версия?
Файловая областьВидит ли код только рабочую папку или другие файлы тоже?
СетьМожет ли код обращаться к внешним сайтам и API?
БиблиотекиКакие пакеты уже установлены и можно ли добавлять новые?
РесурсыЕсть ли ограничения времени, памяти, вычислительной мощности и размера файлов?
СостояниеСохраняются ли переменные и созданные файлы между запусками?
ХранениеКак долго провайдер хранит входы, код и результаты?
ВыходыМожно ли увидеть код, ошибки, таблицы и созданные файлы?

У этих вопросов нет универсальных ответов. Возможности различаются между продуктами и меняются со временем. Записывай только то, что подтверждено интерфейсом, настройками организации или актуальной документацией. Неизвестное помечай как unknown, а не угадывай.

Execution trace: доказательства одного запуска

Execution trace, или журнал исполнения, — связанная запись того, что было запущено и что произошло:

план и входы
+ сгенерированный код
+ среда и известные ограничения
+ статус, ошибки и исправления
+ результаты и созданные файлы
+ проверки и решение человека

Один финальный ответ модели не является полным журналом. Если первая версия кода упала, а вторая сработала, полезно сохранить обе: ошибка показывает, что менялось и почему финальный результат отличается.

Три уровня проверки

1. Безопасность исполнения

Проверь, что код запускается не в основном процессе и получает только допустимые возможности. Это снижает риск доступа к локальным файлам, секретам, сети и ресурсам.

2. Корректность анализа

Сопоставь AnalysisPlan с кодом строка за строкой:

Поле планаЧто искать в коде и результате
ИсточникОткрыт именно согласованный файл
Grain и row IDСтроки не задвоены и считаемая единица не изменилась
ПериодПрименён нужный период
ФильтрыВсе условия включения и исключения присутствуют
МетрикаИспользованы правильная колонка, агрегат и единица
РазрезГруппировка выполнена по нужной колонке
ПроверкиВидны read / used / excluded, полный итог и сверка

Показанный код делает расчёт проверяемым, но не проверяет себя автоматически. Код может быть аккуратным, воспроизводимым и неверным по смыслу.

3. Допустимость данных

Даже хороший sandbox не даёт разрешения загружать в него любые данные. До загрузки проверь правила организации, чувствительность колонок, одобренный продукт, настройки хранения и необходимость обезличивания. Неизвестная политика хранения — причина остановиться и уточнить, а не предположить удаление «после чата».

Разбор двух журналов

Запуск A: технически успешный, аналитически неверный

input: sales.csv, 6 строк
code filter: quarter == Q2
execution status: success
rows read / used / excluded: 6 / 5 / 1
overall: 270 RUB

Проверка:

  • среда исполнила код без ошибки;
  • период Q2 применён;
  • фильтр status=paid отсутствует;
  • использовано 5 строк вместо ожидаемых 4;
  • итог 270 не совпадает с ожидаемой сверкой 200.

Решение: reject. Безопасный запуск не компенсирует неверный фильтр.

Запуск B: технически и аналитически согласованный

import pandas as pd

df = pd.read_csv("sales.csv")
selected = df.query("quarter == 'Q2' and status == 'paid'")
groups = selected.groupby("region")["amount"].sum().sort_values(ascending=False)
overall = selected["amount"].sum()
execution status: success
rows read / used / excluded: 6 / 4 / 2
groups: Москва 150, Питер 30, Казань 20
overall: 200 RUB
reconciliation: 150 + 30 + 20 = 200

Решение: accept для учебного вопроса, если sales.csv является согласованным источником и загрузка данных разрешена.

Сравнение показывает центральный механизм:

Среда изолированаПо контракту средыПо контракту среды
Все фильтры плана примененыНетДа
Итог сошёлсяНетДа
РешениеRejectAccept

ОФЛАЙН-ПРАКТИКА: принять или отклонить запуск

Сценарий

План требует источник sales.csv, фильтры Q2 + paid и итог 200. Журнал сообщает:

input file: sales-final-v2.csv
rows read / used / excluded: 6 / 4 / 2
code filters: quarter == Q2 and status == paid
overall: 200 RUB
execution status: success
environment: отдельная среда; сеть запрещена; срок хранения unknown

Ответь письменно:

  1. Какое решение принимаешь: accept, reject или needs clarification?
  2. Какие доказательства уже достаточны?
  3. Какой факт отсутствует?
  4. Какое минимальное действие разблокирует решение?

Сильный ответ — needs clarification: код и числа согласованы, но имя входного файла отличается от утверждённого источника, а связь версий не подтверждена. Нужно подтвердить происхождение sales-final-v2.csv или повторить запуск на согласованном файле. Неизвестный срок хранения отдельно блокирует загрузку рабочих чувствительных данных, но не мешает учебному синтетическому примеру.

Реалистичные ошибки

  • Считать зелёный статус доказательством правильности. success означает, что код завершился, но не подтверждает фильтры, метрику и источник.
  • Назвать урезанный exec песочницей. Ограничение функций внутри основного процесса не создаёт изоляцию по процессам, файлам и ресурсам.
  • Проверить код, но не вход. Правильный расчёт над другой версией файла отвечает на другой набор данных.
  • Проверить только финальную версию. Скрытая ошибка и автоматическое исправление могут изменить метод; сохрани обе версии.
  • Предположить отсутствие сети или мгновенное удаление данных. Возможности и хранение зависят от продукта и конфигурации; неизвестное остаётся неизвестным.
  • Загрузить рабочие данные до проверки политики. Sandbox ограничивает код, но не отменяет правила доступа, хранения и передачи данных.
  • Просить только число. Для приёмки нужны код, read / used / excluded, полный итог и сверка.
  • Считать показанный код достаточным. Его ещё нужно сопоставить с утверждённым AnalysisPlan.

## Критерий готовности

Карточка готова, если другой человек без доступа к чату может:

1. назвать утверждённый вход и план;
2. увидеть точный код и историю исправлений;
3. отделить подтверждённые ограничения среды от неизвестных;
4. воспроизвести проверки результата;
5. объяснить решение `accept / reject / needs clarification`;
6. выполнить указанное следующее действие.

Часы: ~4 · DoD: студент отличает модель от среды исполнения; по журналу обнаруживает пропущенный фильтр и неподтверждённый источник; карточка связывает план, вход, код, ограничения, результат и решение; недоверенный код не запускается локально. ✅ Урок готов
