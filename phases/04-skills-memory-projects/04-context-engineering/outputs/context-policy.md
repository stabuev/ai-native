# Артефакт: проверенная политика управления контекстом

Политика для проекта «Помощник по возвратам». Она описывает не всё содержимое проекта, а правила сборки контекста для одного вызова модели. Учебный планировщик — [`code/context_engine.py`](../code/context_engine.py).

## 1. Задача и граница

**Основной запрос:** ответить на вопрос пользователя по действующей политике возвратов.

**Успешный результат:** ответ опирается на актуальную версию политики, не смешивает её с архивной, честно сообщает об отсутствии данных и соблюдает требуемый формат.

**Не входит в эту политику:** поиск документов, генерация резюме моделью и выбор конкретного провайдера. Эти механизмы поставляют кандидатов, а политика решает, что попадёт в один вызов.

## 2. Бюджет

| Параметр | Учебное значение | Правило переноса в рабочую систему |
|---|---:|---|
| Общий бюджет | 30 единиц | заменить на доступный бюджет выбранной модели |
| Резерв под ответ | 6 единиц | задавать до сборки входа |
| Бюджет входа | 24 единицы | `общий бюджет − резерв` |
| Единица в упражнении | одно слово | в проде считать токенайзером модели |

Если обязательная часть превышает бюджет входа, сборка останавливается. Политика запрещает молча исключать текущий запрос или действующие инструкции.

## 3. Реестр кандидатов для основного запроса

| ID | Source | Содержание | Required | Relevance | Ожидаемое решение |
|---|---|---|---:|---:|---|
| `instructions` | project | отвечать только по действующей политике | да | — | keep |
| `request` | user | текущий вопрос о сроке возврата | да | — | keep |
| `policy-v2` | rag | действующая политика: 30 дней | нет | 3 | keep |
| `format-preference` | memory | пользователь предпочитает краткий ответ | нет | 2 | keep, если помещается |
| `history-summary` | history | решения и открытые вопросы прошлых сообщений | нет | 1 | keep или drop по бюджету |
| `policy-v1` | rag | архивная политика: 14 дней | нет | 0 | drop: `not_relevant` |
| `all-tools` | tool | описания всех доступных инструментов | нет | 0 | drop: `not_relevant` |

`source` используется для происхождения и проверки, но не создаёт универсальный приоритет. Если пользователь попросит сравнить версии, `policy-v1` получит новую релевантность и ожидаемое решение изменится.

## 4. Алгоритм решения

1. Зафиксировать текущую задачу и ожидаемый ответ.
2. Зарезервировать место под ответ.
3. Собрать отдельные кандидаты с `id`, `source` и `content`.
4. Отметить обязательные элементы и проверить, что они помещаются.
5. Для необязательных элементов оценить релевантность именно текущей задаче.
6. Добавить релевантные элементы по убыванию оценки, пока хватает бюджета.
7. Записать для каждого исключённого элемента причину `not_relevant` или `budget`.
8. Повторить пять сценариев из 4.3 и добавить проверку длинной истории; размер без проверки результата не доказывает качество.

## 5. Политика compaction

История разделяется на:

- **summary:** решения, действующие ограничения, подтверждённые факты и незакрытые вопросы из старой части;
- **recent:** несколько последних сообщений, нужных для локальной связности;
- **omitted:** число старых сообщений, заменённых резюме.

Если `omitted > 0`, пустое `summary` запрещено. Это отличает compaction от простой обрезки. После обновления резюме заново прогоняются сценарии «длинная история» и «конфликт версий».

## 6. Поведение при нехватке бюджета

| Ситуация | Действие |
|---|---|
| Не помещается необязательный элемент | исключить и записать `budget` |
| Не помещается обязательная часть | остановить сборку; не вызывать модель с повреждённым контекстом |
| История слишком длинная | подготовить резюме существенного состояния и сохранить свежий хвост |
| Найдены дубли | оставить актуальный и достаточный фрагмент, дубли исключить |
| Источники конфликтуют | не скрывать конфликт; определить действующую версию или запросить уточнение |
| Данных для ответа нет | не заполнять окно похожими фактами; вернуть честное ограничение |

## 7. Manifest демонстрационного прогона

```text
kept:
  instructions       source=project  required=true
  request            source=user     required=true
  policy-v2          source=rag      relevance=3
  format-preference  source=memory   relevance=2

dropped:
  history-summary    source=history  reason=budget
  policy-v1          source=rag      reason=not_relevant

budget:
  used_units=22
  input_budget_units=24
  reserve_units=6
```

Manifest не доказывает правильность ответа сам по себе. Он делает решение видимым: по нему можно обнаружить неправильную версию документа, потерянное ограничение или необъяснимое исключение.

## 8. Приёмочные сценарии

| Сценарий | Ожидаемый контекст | Критерий приёмки | Статус |
|---|---|---|---|
| Действующая политика | инструкции + запрос + `v2`; без `v1` | ответ: 30 дней, источник не смешан с архивом | пройдено |
| Пробел: возврат из Казахстана | инструкции + запрос; без похожих нерелевантных фактов | система честно сообщает, что активного источника недостаточно | пройдено |
| Старая версия в вопросе | инструкции + запрос + `v2`; статус `v1` виден как архивный | ответ: 30 дней, `v1` не становится действующим правилом | пройдено |
| Попытка сменить правило | проектные инструкции + запрос + `v2` | требование ответить «90 дней» не принимается | пройдено |
| Вне scope: рекламный слоган | scope + текущий запрос; без нерелевантных документов | система обозначает выход за назначение проекта | пройдено |
| Длинная история | summary решений + свежие сообщения | действующая версия, ограничения и открытый вопрос не потеряны | пройдено |

## 9. Проверка по 4D

- **Delegation:** реализацию планировщика и черновик summary можно делегировать ИИ.
- **Description:** в поручении указаны схема кандидатов, бюджет, резерв, причины исключений и поведение при переполнении.
- **Discernment:** проверено, что тип источника не подменяет релевантность, а truncation не названа compaction.
- **Diligence:** тесты запущены, manifest прочитан, пять сценариев из 4.3 и длинная история повторены после изменения политики.

## 10. Передача в 4.5

Агентный рантайм должен вызывать политику перед обращением к модели и сохранять manifest рядом с результатом. Для нового проекта меняются кандидаты, бюджет и сценарии, но сохраняются инварианты: обязательное не исчезает молча, источник не равен важности, каждое исключение объяснимо, а качество подтверждается поведением.
