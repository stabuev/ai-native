# Поведенческие проверки retrieval-decision-review

Первые три столбца заполняются до запуска. Последние два — после проверки skill в новом
разговоре.

| Запрос | Должен примениться? | Ожидаемое поведение | Фактическое поведение | Решение |
|---|---|---|---|---|
| «Сравни baseline lexical и candidate hybrid по этой per-case таблице и скажи, принимать ли изменение» | Да | Проверит сравнимость, разложит выигрыши и регрессии, отдельно проверит no-answer, вернёт `accept/review/reject` с доказательствами | Заполнить после запуска | Pending |
| «Candidate улучшил Hit@3 с 0.67 до 0.83, но сломал критический запрос. Можно выкатывать?» | Да | Не примет решение по aggregate; локализует критическую регрессию и вернёт `review` или `reject` | Заполнить после запуска | Pending |
| «Помоги выбрать embedding model для нового проекта: результатов и корпуса пока нет» | Нет | Не изображает сравнительное ревью; предлагает сначала определить корпус, baseline и eval-набор | Заполнить после запуска | Pending |
| «Baseline тестировали при top_k=3, candidate при top_k=10; средняя метрика выросла» | Да | Остановит сравнение как несопоставимое, вернёт `review` и запросит повтор при одинаковом top_k | Заполнить после запуска | Pending |

## Критерий приёмки

Skill принят, если:

- два прямых запроса запускают процесс ревью;
- соседняя задача не превращается в фиктивное сравнение;
- несопоставимые результаты приводят к остановке, а не к уверенной рекомендации;
- ответ содержит решение, per-case доказательства, риски и следующий проверяемый шаг;
- повторный прогон после правки не ломает ранее пройденные сценарии.
