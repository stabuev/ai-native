# Артефакт: шаблон guardrails для агента

Заслоны между решением агента и действием. Код — [`code/guardrails.py`](../code/guardrails.py).

## Уровни защиты и их владельцы

```
HOST / agent runtime
 действие агента
  1. ВАЛИДАЦИЯ аргументов  → типы, лимиты, разрешённые операции
  2. ПОДТВЕРЖДЕНИЕ (HITL)  → pause / approve / reject для конкретного риска
  3. ВЫЗОВ MCP CAPABILITY
             │
             ▼
MCP SERVER
  4. TRUSTED CONTEXT + АВТОРИЗАЦИЯ action/object  → урок 6.5
  5. ИСПОЛНЕНИЕ + АУДИТ
```

Approval в host не выдаёт право и не заменяет policy: после `approve` MCP server всё
равно должен отклонить caller без permission или объект вне разрешённой границы.

## Какие действия опасны (требуют подтверждения)

`delete` · `send_money` · `send_email` · `deploy` · `drop_table` · массовые изменения · всё необратимое или с внешним эффектом.

## Шаблон

```python
from guardrails import run_action, amount_limit

result = run_action(
    {"tool": "send_money", "args": {"amount": 50, "to": "Иван"}},
    tools,
    confirm=ask_human,                 # callable(action)->bool: пауза на approve/reject
    validators=[amount_limit(100)],    # проверки до исполнения
)
```

## Правила

- **Безопасные действия — без трения**, опасные — только после approve.
- **Валидируй до подтверждения**: плохие аргументы не должны доходить до человека.
- **Дешёвый guardrail-модель** отсекает плохое до дорогого вызова (экономия, Фаза 9).
- **Подтверждение = пауза, а не новый ход**: сохраняй состояние и продолжай (resume).
- **Аудит** каждого решения (кто, что, разрешено ли); алерты на отказы.
- Данные из инструментов недоверенные → возможны prompt-инъекции (Фаза 11).
