# Артефакт: проверяемый аналитический brief

Этот brief — краткий паспорт смысла и исполнения расчёта — фиксирует договорённости до того, как ИИ напишет код. Скопируй шаблон в свою
папку, замени учебный пример собственным вопросом и приложи исполненный план с
проверками. Механика офлайн-исполнителя — [`code/analyze.py`](../code/analyze.py).

## 1. Решение и граница вопроса

| Поле | Что зафиксировать |
|---|---|
| Решение | Какое действие будет принято по результату |
| Описательный вопрос | Какое число или сравнение нужно получить |
| Не исследуем | Причины, прогнозы и другие выводы, которых этот расчёт не доказывает |
| Владелец определения | Кто подтверждает смысл метрики и фильтров |

Если вопрос звучит как «почему продажи упали?» или «что произойдёт дальше?», простой
групповая агрегация может подготовить наблюдения, но не доказать причину и не дать
надёжный прогноз.

## 2. Контракт данных

| Поле | Что зафиксировать |
|---|---|
| Источник | Имя файла, таблицы или системы |
| Период | Какие даты или периоды входят |
| Grain | Что означает одна строка |
| Row ID | Какая колонка отличает одну единицу наблюдения |
| Нужные колонки и типы | Название, смысл, ожидаемый тип |
| Известные ограничения | Пропуски, дубли, неполная выгрузка, часовой пояс, валюта |

Grain проверяется до агрегации. Если одна строка означает позицию заказа, `COUNT(*)`
считает позиции, а не уникальные заказы.

## 3. Определение метрики

| Поле | Что зафиксировать |
|---|---|
| Название | Понятное бизнес-имя |
| Формула | Например `SUM(amount)` |
| Фильтры | Какие строки включаются и исключаются |
| Разрез | По какой колонке сравниваются группы |
| Единица | Рубли, заказы, проценты, минуты |
| Top-N | Сколько лидеров показать и как показать остаток |

Колонка `amount` сама по себе не является метрикой. Метрика появляется, когда определены
формула, фильтры, период и единица результата.

## 4. План исполнения

```python
PLAN = {
    "question": "...",
    "source": "...",
    "grain": "...",
    "row_id": "...",
    "period": "...",
    "filters": {"column": "expected value"},
    "metric": {
        "name": "...",
        "column": "...",  # для count_rows укажи row_id считаемой единицы
        "aggregation": "sum | mean | count_rows",
        "unit": "...",
    },
    "group_by": "...",
    "top_n": 5,
}
```

ИИ может предложить этот план, но владелец вопроса проверяет его до исполнения. Не проси
модель угадывать неизвестное определение метрики.

## 5. Проверки результата

- [ ] Прочитанное число строк совпадает с выгрузкой.
- [ ] Видно, сколько строк использовано и исключено фильтрами.
- [ ] Row ID заполнен и уникален согласно заявленному grain.
- [ ] Нужные колонки существуют, а значения метрики имеют ожидаемый тип.
- [ ] Для `sum` и `count_rows` итог всех групп сходится с общим итогом.
- [ ] Для `mean` среднее групп проверяется с весами, а не простым сложением.
- [ ] Top-N не выдаётся за полный итог: остаток показан отдельно.
- [ ] Вывод не выходит за границу описательного вопроса.

## Заполненный учебный пример

### Вопрос

Какие регионы принесли больше оплаченной выручки в Q2?

### Контракт

| Поле | Значение |
|---|---|
| Источник | `sales.csv` |
| Grain | Одна строка = один заказ |
| Row ID | `order_id` |
| Период | `quarter = Q2` |
| Метрика | `paid_revenue = SUM(amount)` |
| Фильтры | `quarter = Q2`, `status = paid`; возвраты и другие периоды исключаются |
| Разрез | `region` |
| Единица | RUB |
| Формат | Top-2 региона, остальные отдельно, полный итог и проверки |

### План

```python
PLAN = {
    "question": "Какие регионы принесли больше оплаченной выручки в Q2?",
    "source": "sales.csv",
    "grain": "одна строка = один заказ",
    "row_id": "order_id",
    "period": "Q2",
    "filters": {"quarter": "Q2", "status": "paid"},
    "metric": {
        "name": "paid_revenue",
        "column": "amount",
        "aggregation": "sum",
        "unit": "RUB",
    },
    "group_by": "region",
    "top_n": 2,
}
```

### Ожидаемый результат

| Показатель | Значение |
|---|---:|
| Строк прочитано | 6 |
| Строк использовано | 4 |
| Москва | 150 |
| Питер | 30 |
| Остальные регионы | 20 |
| Общая оплаченная выручка Q2 | 200 |

Проверка выполняется по всем группам до обрезки top-2:

```text
150 + 30 + 20 = 200
top-2 = 180
other = 20
180 + 20 = 200
```

Этот расчёт показывает распределение оплаченной выручки по регионам. Он не доказывает,
почему один регион сильнее другого и сохранится ли результат в следующем квартале.
