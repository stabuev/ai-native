# Артефакт: карточка проверки исполнения

Карточка связывает утверждённый аналитический план с конкретным запуском. Она не доказывает безопасность платформы сама по себе: факты о среде должны опираться на интерфейс, настройки организации или актуальную документацию.

## 1. Решение и утверждённый план

| Поле | Что зафиксировать |
|---|---|
| Решение | Какое действие поддерживает расчёт |
| Вопрос | Какой описательный вопрос исполняется |
| Версия плана | Где лежит согласованный `AnalysisPlan` и кто его подтвердил |
| Ожидаемый результат | Read / used / excluded, группы, полный итог и сверка |

## 2. Входные данные

| Поле | Значение |
|---|---|
| Имя и версия файла | |
| Происхождение | Кто и откуда получил выгрузку |
| Grain и row ID | |
| Число строк | |
| Чувствительность | Синтетические / внутренние / персональные / другое |
| Разрешение на загрузку | Кто или какое правило разрешает использование инструмента |

Если имя или версия не совпадают с планом, не исправляй запись задним числом. Подтверди связь версий либо повтори запуск.

## 6. Решение по запуску

Выбери одно:

- `accept` — вход, код, результат и допустимость среды подтверждены для этого решения;
- `reject` — найдено существенное расхождение;
- `needs clarification` — для решения не хватает конкретного факта.

## Заполненный учебный пример

```text
План: Q2 + paid, SUM(amount) по region, ожидаемый итог 200 RUB.
Вход: sales.csv, синтетический, 6 строк.
Код: применил только quarter == Q2.
Статус: success.
Read / used / excluded: 6 / 5 / 1.
Итог: 270 RUB.
Среда: отдельная; остальные ограничения для этого примера не влияют на решение.

Вердикт: reject.
Доказательство: отсутствует status == paid, использована лишняя строка возврата.
Следующее действие: исправить фильтр, повторить запуск и получить 6 / 4 / 2 и 200 RUB.
```

## Критерий готовности

Карточка готова, если другой человек без доступа к чату может:

1. назвать утверждённый вход и план;
2. увидеть точный код и историю исправлений;
3. отделить подтверждённые ограничения среды от неизвестных;
4. воспроизвести проверки результата;
5. объяснить решение `accept / reject / needs clarification`;
6. выполнить указанное следующее действие.
